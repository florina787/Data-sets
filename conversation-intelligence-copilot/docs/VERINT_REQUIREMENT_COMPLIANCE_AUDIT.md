### 2.5 Agent workflow

- **Every node runs and is recorded.** Recorded paths (from Decision Replay of the live runs):
  - Q1: … supervisor → topic_agent → evidence → … (no FAISS)
  - Q2: … supervisor → coaching_agent → retrieval (hybrid, 4 passages) → …
  - Q3: … supervisor → sentiment_agent → evidence → … (2 DuckDB ops)
  - Q4: … supervisor → leadership_agent → retrieval (hybrid, 3) → …
- **Computation is deterministic:** registered, parameterised operations only, with no model-written SQL (`query_registry.py run_operation`).
- **No model calls for the four questions.** In AUTO mode the router keeps fact questions off the model.
- **The model is really invoked when needed.** This audit called it 3 times in a fresh process: 8.7 s cold, 0.9 s and 0.8 s warm, 662–664 tokens reported.
- **Routing is reproducible.** The test split re-scored identically (95.9%, macro F1 0.932).
- **Errors and unavailable providers:** the outage, corrupt index, missing database, missing local model file and circuit-breaker tests pass (`test_api_and_failures.py`, `test_providers.py`, `test_gemini_adapter.py`).
- **Decision Replay is built only from recorded telemetry** (`observability/replay.py:41`).
- **Evidence validation is not bypassed:** QA and the challenger run in the graph's fixed `qa` node, on every path.
- **Result: PASS.**
