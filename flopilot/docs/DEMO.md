# Demo walkthrough

All data in the demo workbook is **synthetic** (generated by `backend/scripts/generate_demo_workbook.py`, fixed seed). The app runs in **Demo mode** (badge in the header): a deterministic planner, no AI model. Integrations other than the local app are not connected.

## Demo workbook

| Sheet | Contents | Seeded issues |
|---|---|---|
| Sales (120 rows) | Orders Jan–Jun 2025: date, product, category, region, customer, units, prices, gross/net revenue, cost, `Profit` formula (`=K-L`) | Region variants (`north america`, `Europe `, `EUROPE`, `Asia Pacfic`), category typo `Accesories`, missing Region/Customer ID/Discount, 8 dates stored as text in 3 formats, `Units` stored as text in one row, an unusual 250-unit laptop order (row 75), two re-keyed duplicate orders and one repeated Order ID, a typed-over Profit formula (row 40) |
| Expenses (60 rows) | Department spend vs budget with `Variance %` formula | `Budget = 0` in row 23 → `#DIV/0!`; department typo `Marketng`; one missing Amount |
| Inventory (15 rows) | Excel table `InventoryTable`, `Stock Value` formula, conditional formatting, data validation | Used to show feature preservation |
| Customers (41 rows) | Customer master | Missing Segment ×3, exact duplicate customer C017 |
| Summary | KPI formulas over Sales and Expenses, merged title | Cross-sheet references (blocks unsafe row deletion in Sales) |
| Notes (hidden) | A synthetic prompt-injection string | Flagged; never followed |

## Script (≈5 minutes)

1. **Sign in** as *Florina (demo analyst)* → **Open the synthetic demo workbook**. Point out the Excel-style grid, sheet tabs, formula bar, data-quality panel (1 error, warnings, notes) and the FloMin welcome.
2. **Analyse with ambiguity**: type “Summarize revenue by region”. FloPilot asks *Gross Revenue or Net Revenue?* → choose **Net Revenue**. Show the table/chart, the “How this was calculated” section (method, missing-data treatment, warning about spelling variants) and click the **Sales!K2:K121** source: the grid selects it and the status bar shows the same Sum.
3. **Month-over-month**: “Which products had the largest month-over-month decline in net revenue?”.
4. **Clean**: “Clean the Sales sheet” → four proposals (Category spelling, Region spelling, Order Date text dates, Units text number). **Preview in grid**, toggle **Before/After**, **Approve & apply** the first. Try approving the second: it is out of date (workbook now v2) → **Prepare again for current version** → approve.
5. **Formula**: “Add a profit-margin column using net revenue” → formula `=IFERROR(M2/K2,"")`, meaning, inputs, behaviour, compatibility, preview values (and “Verified by LibreOffice” if installed) → approve. The grid shows the new column with percentages.
6. **Diagnose**: “Fix the formula error in Expenses!H23” → explanation (Budget G23 is zero) and a flagged formula replacement.
7. **Safety**: “Remove the duplicates on Sales” → refused (Summary formulas reference those rows) with “Flag duplicates instead”. “Remove the duplicates on Customers” → a destructive proposal clearly marked *Deletes 1 row*.
8. **Report**: “Compare actual spending with budget” → **Add to workbook as a report** → approve → new sheet with a native bar chart. Export ▸ Download workbook (.xlsx).
9. **Recover**: **Activity** ▸ Versions ▸ *Restore this version…* on version 1 → approve → the workbook is back to the original (as a new version; history kept). Show the *Requests & usage* tab (tool steps, 0 tokens in demo mode) and the *Audit trail*.
10. **Roles**: sign out, sign in as *Victor (demo viewer)*: the viewer can read and ask questions, but proposals are refused and approve/export are disabled.

Analyze data · Create formulas · Build a chart · Clean & restore — every suggested prompt is covered by `backend/tests/test_suggested_prompts.py`, which parses them from the UI source and runs each one in demo mode.
